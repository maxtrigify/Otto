# Saved bot subagents

In **Manage agents**, select a bot and use **Subagents → Add subagent**. Set the helper's name, job, provider (Codex or Claude Code), account (This Mac’s login or a saved profile), and model, then save the bot. Saving authorises that bot to send tasks to the selected account. The parent bot's subscription remains independent. **This Mac’s login** explicitly uses the chosen provider’s local login, even when a project or global default names another account. It is available without creating a saved profile. `Provider default` leaves model selection to that provider; selecting a model fixes its identifier.

The bot receives its configured helper IDs in bootstrap context. It calls `agent.spawn` with `subagentID` and a task. Otto resolves the current saved configuration against the calling node's profile, overrides agent-supplied provider/account/model, and bounds permissions to the parent's mode. Existing spawn throttling, child tracking, completion events and result retrieval apply. This is Otto-managed delegation across separate CLI sessions; native in-provider subagents are a separate mechanism.

An unknown helper, a helper belonging to another bot, a removed helper, an archived parent or an unavailable named account fails before launch. Saved helper sessions retain a strict account requirement on subsequent launches, avoiding the ordinary account fallback chain. A helper gets the task brief and role, not the parent's saved bot identity/private notes or its helper configuration. General workspace/project bootstrap still applies. This does not provide OS sandboxing against unrestricted local tools.

Older profiles decode without helpers. Local account choices and helper routes are omitted from portable bot share manifests. Existing named-account model discovery is reused: Claude supplies stable aliases rather than account-specific entitlement discovery; Codex discovery can require a populated login model cache. No automatic retry on a different model or subscription is introduced.
