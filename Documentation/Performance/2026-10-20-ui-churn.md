# UI churn investigation — 20 October 2026

## Observations

- Fetched origin: integration `main` already included `origin/main` and was 16 commits ahead at the start (`1c5cbd0`).
- Both installed Otto 0.1.59 (126) and Otto Dev were running. The installed release consumed approximately 101–109% CPU in two observations; Dev was approximately 0.2–3.6%.
- A five-second `sample` of the installed release placed 1,591 of 2,094 main-thread samples in run-loop observers, including 1,149 in SwiftUI transaction flushing. Native popup/control updates and accessibility label work dominated large branches. This is evidence of UI update pressure, not a measured input-latency benchmark.
- Sidebar evaluation also repeatedly called `AgentFleetStore.snapshots`, which constructs a dictionary containing every runtime snapshot, for individual bot lookups.
- The development app's three-second sample showed its main thread waiting for events. These apps had different workloads; this is not a release-versus-debug performance comparison.

## Changes

Streaming provider parsers emit `.working` for messages and deltas. The supervisor previously forwarded even identical state/confidence pairs as lifecycle events. ApplicationServices responds to these with published diagnostics/history updates, which invalidate broad portions of the UI. Suppress identical working/idle parser state notifications; raw output continues to trigger coalesced per-agent rendering. Waiting, permission, terminal, changed-confidence, and actual state changes retain their existing behavior.

Bot roster lookups now read the keyed fleet model directly instead of copying the entire fleet twice per bot.

The regression test feeds 100 Hermes deltas through a real child process and verifies one working lifecycle event plus the final response. Existing supervisor tests cover lifecycle, permission, and completion behavior.

## Limits and follow-up

These are concrete sources of avoidable work and plausible contributors to the sampled lag. The live installed release has not been replaced or restarted, so there is no measured post-fix CPU or interaction-latency improvement yet. Compare the rebuilt app under the same active-agent workload before claiming the lag is fully resolved. Raw sampling reports remain local and are not checked in.

## Validation

- `scripts/otto-swift test --filter AgentSupervisorTests --no-parallel --jobs 4`: build succeeded; all 24 supervisor tests passed, including the 100-delta regression.
- Strict swift-format lint for the three changed Swift files and `git diff --check` passed.
- `Package.resolved` unchanged. Existing compiler warnings in unrelated automation code remain.
